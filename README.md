# PID Dataset v1.1 Full

## Призначення

Єдиний синтетичний датасет для подальшого **незалежного порівняння** структурованої PIDNN, звичайної RNN, LSTM та NARX. Датасет генерується відкритим за циклом еталонним дискретним ПІД-законом; він **не доводить стійкості замкненого контуру**. На цьому етапі жодну модель не навчали.

## Структура

| Набір | Звичайні послідовності | Довгі послідовності | Загальна кількість відліків |
|---|---:|---:|---:|
| Train (`train.csv`) | 240 × 1024 | 12 × 4096 | 294 912 |
| Validation (`validation.csv`) | 60 × 1024 | 4 × 4096 | 77 824 |
| Test (`test.csv`) | 60 × 1024 | 12 × 8640 | 165 120 |
| **Разом** | **360** | **28** | **537 856** |

**Загалом 388 незалежних часових послідовностей.** `sequences.csv` містить ідентифікатори, набір, тип сигналу, режим z та випадкові зерна. Усі відліки однієї послідовності зберігаються лише в одному наборі. Короткі послідовності охоплюють усі 8 погоджених типів похибки в кожному наборі. Довгі — `long_hold` і `long_z_comp`, зі зміною знака й масштабу між незалежними реалізаціями.

Стовпці CSV: `sequence_id,k,time_s,signal_type,z_mode,e,z_1,...,z_q,Kp,Ki,Kd,P,I,D,u_P,u_I,u_D,u`. Формат і порядок стовпців збігаються з Pilot v1.1.

## Незмінний дискретний еталон

`Ts=10` секунд, початково `I[-1]=0`, `e[-1]=0` **тільки на початку нової незалежної послідовності**.

- `P[k] = e[k]`
- `I[k] = I[k-1] + 10*e[k]`
- `D[k] = (e[k]-e[k-1])/10`
- `u[k] = Kp(z[k])*P[k] + Ki(z[k])*I[k] + Kd(z[k])*D[k]`

Немає насичення виходу, обмеження/скидання інтеграла, фільтра похідної чи anti-windup. Розрахунки `float64`; CSV зберігає числа з точністю `.17g`. Початково `q=4`, параметр змінюється через командний рядок.

Коефіцієнти залишаються точно як у Pilot v1.1:

`Kp = 1*(1 + 0.3 * (z @ wp))`

`Ki = 0.005*(1 + 0.4 * (z @ wi))`

`Kd = 5*(1 + 0.4 * (z @ wd))`

Для `q=4`: `wp=[0.4,0.3,-0.2,0.1]`, `wi=[-0.1,0.4,0.3,-0.2]`, `wd=[0.1,-0.3,0.2,0.4]`. Для довільного `q` зберігаються фіксовані L1-нормовані вектори ваг. Для `q>=2` перевіряється попарна непропорційність; для `q=1` вона математично незастосовна.

## Спеціальні випадки Full (виправляють слабке покриття Pilot)

- У **кожному** з Train, Validation і Test входи `e` мають фактично `-1` і `+1`.
- Для `q=4` кожен набір включає усі **16 вершин** гіперкуба `z_j=±1`, внесені як незалежні послідовності з постійним z. Це досягає крайніх значень усіх Kp, Ki, Kd без обрізання самих коефіцієнтів. Для `q<=4` проходяться усі `2**q` вершини; для `q>4` використовуються 16 вибраних вершин, включно із крайніми за кожним коефіцієнтом. Повний перебір `2**q` для великих q не обіцяється.
- У всіх послідовностях зі `z_mode=step` є **мінімум одне реальне перемикання**. Використовується перевірена `make_z()` з Pilot v1.1.
- Для довгих експериментів внутрішні стани еталонного ПІД не скидаються до кінця незалежної послідовності. `test.csv` має 12 незалежних експериментів по 8640 відліків (24 години за Ts=10 с).
- Довгі послідовності навмисно мають високий внесок інтеграла; поріг домінування 5% для P/I/D перевіряється **для коротких послідовностей**. Для довгих відсотки наведені окремо без штучного урівнювання.

## Як запустити

Потрібні Python 3.10+ та `numpy`, `matplotlib`:

```bash
python -m pip install numpy matplotlib
python pid_dataset_full_v1_1.py --q 4 --seed 20261102 --out pid_full_v1_1
```

Файл **`pid_dataset_pilot_v1_1.py` повинен лежати поруч із `pid_dataset_full_v1_1.py`**, тому що новий скрипт **імпортує перевірені функції Pilot**, а не переписує їх. Для q=1 або q=2 змінити `--q`. Для запуску без PNG додати `--no-plots`.

## Верифікація й відтворюваність

`validation_report.json` зберігає **незалежно від генератора перевірені по CSV** результати кожного набору: `mathematical_validation` і `coverage_validation` з окремими `PASS/FAIL`, реальні min/max, вершини z, перемикання z, активність та домінування P/I/D коротких і довгих послідовностей. `config.json` зберігає всі експерименти, початкові випадкові зерна, матрицю ваг, припущення, розміри та формули. `manifest_sha256.json` містить контрольні суми.

Генератор запущено **двічі** з `--q 4 --seed 20261102`: CSV, JSON та `sequences.csv` збіглися за SHA-256. Побудовано 38 діагностичних PNG. Математичні перевірки, усі покриття за визначеною політикою та міжнабірна незалежність пройдені.

## Чого поки не перевірено

1. Реалістичність похибки та параметрів для конкретного зерносховища і фізичного приводу.
2. Роботу в замкненому контурі, стійкість та насичення реального виконавчого механізму.
3. Узагальнення на невідомі **нелінійні** функції K(z) (зараз закон лінійний).
4. Достатність кількості відліків для досягнення заданої точності конкретною RNN/LSTM/NARX/PIDNN: це можна визначити тільки після навчання й окремої перевірки.
5. Необмежену тривалість пам’яті: найдовший тест триває 24 години.

**Під час навчання** лише `e` та `z_1 ... z_q` є зовнішніми входами; еталонні `P,I,D,u_P,u_I,u_D` не передаються як входи. `u` — основна ціль; `Kp,Ki,Kd` можуть бути допоміжними цілями. Стан між фрагментами однієї послідовності не скидати; на межі незалежних `sequence_id` — скидати. Статистики нормалізації оцінювати тільки на Train. Під час оцінювання NARX використовувати власні попередні прогнози, якщо так визначена структура моделі, а не підставляти еталонні керувальні сигнали з тестового CSV.
